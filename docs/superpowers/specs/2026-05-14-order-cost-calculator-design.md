# Калькулятor себестоимости заказа — дизайн

**Дата:** 2026-05-14
**Статус:** утверждён

## Проблема

Текущая формула расчёта стоимости печати (`calculatePrice` в `lib/utils.ts`)
учитывает только вес материала и цену за грамм. Она не отражает реальную
себестоимость: электричество, амортизацию принтера, расходники, работу
оператора, процент брака, налоги и наценку.

Нужно:
1. Дать менеджеру в админке инструмент для расчёта реальной цены заказа.
2. Приблизить клиентскую ориентировочную оценку к реальной себестоимости.

## Объём работы

- Новый модуль `lib/pricing.ts` — единое ядро расчёта.
- Новый компонент `components/admin/CostCalculator.tsx` — калькулятор на странице
  заказа в админке.
- Переписать клиентский расчёт в `components/order/SummaryPanel.tsx` на новое ядро.
- Удалить устаревший `calculatePrice` из `lib/utils.ts`.
- Юнит-тесты на `lib/pricing.ts`.

Параметры калькулятора **нигде не сохраняются** — это транзитный инструмент.
Менеджер получает цифру и подставляет её в существующее поле «Стоимость»
(`Order.estimatedPrice`).

## Архитектура

**Подход A — общее ядро + два потребителя.** Чистая функция
`calculateOrderCost(inputs)` в `lib/pricing.ts` возвращает разбивку и итог.
Её используют оба потребителя: клиентская оценка (дефолтные тарифы + оценка
времени из веса) и админ-калькулятор (все поля редактируемые). Один источник
правды для формулы.

### Модель расчёта (`lib/pricing.ts`)

Входные данные:

```
вес_заказа (кг)   — клиент: оценка из габаритов заказа
                    (габаритный объём × плотность × заполнение × количество);
                    админ: предзаполнено той же оценкой, можно перебить
                    значением из слайсера
время_заказа (ч)  — клиент: оценка из веса (константа г/час);
                    админ: вводится вручную, на весь заказ целиком
```

Формула:

```
материал      = цена_филамента_р_кг × вес_заказа
электричество = тариф × мощность_принтера_кВт × время
расходники    = расходники_р_час × время
амортизация   = амортизация_р_час × время
час_печати    = за_час_печати_р_час × время
оператор      = фикс (на весь заказ)

себестоимость = материал + электричество + расходники + амортизация
                + час_печати + оператор
с_браком      = себестоимость / (1 − брак% / 100)
с_наценкой    = с_браком × коэффициент_наценки
итог          = округл( с_наценкой × (1 + налог% / 100) )
```

Функция возвращает объект с разбивкой по каждой строке и итогом.

### Дефолтные параметры

| Параметр              | Значение по умолчанию |
|-----------------------|-----------------------|
| Тариф (р/кВт·ч)       | 20                    |
| Мощность принтера (кВт)| 0.15                 |
| Расходники (р/час)    | 30                    |
| Шанс брака (%)        | 5                     |
| Работа оператора (р)  | 500                   |
| Амортизация (р/час)   | 50                    |
| За час печати (р/час) | 100                   |
| Налоги (%)            | 13                    |
| Наценка / коэффициент | 1.2                   |

**Цена филамента** — своя на каждый материал, константа `FILAMENT_PRICE_PER_KG`
(ориентир ~1200 р/кг, для дорогих материалов выше).

**Плотности материалов** — переносятся из текущего `MATERIAL_DENSITY` в `lib/utils.ts`.

**Скорость печати** для оценки времени на клиенте — константа г/час
(используется только в клиентской оценке, не в админ-калькуляторе).

## Интерфейс

### Админ-калькулятор

`components/admin/CostCalculator.tsx` встраивается в блок «Стоимость» на
[странице заказа](../../../app/admin/(protected)/orders/[id]/page.tsx).

- Сворачиваемый блок «Калькулятор себестоимости», по умолчанию свёрнут.
- При раскрытии поля предзаполнены: **вес заказа** — авто-оценка из габаритов;
  тарифы — дефолты; **цена филамента** — по материалу заказа; **время печати** —
  пусто, вводит менеджер.
- Все поля — редактируемые `<input type="number">`.
- Под полями — живая разбивка: материал / электричество / расходники /
  амортизация / час печати / оператор → себестоимость → с браком →
  с наценкой → **ИТОГ**.
- Кнопка **«Подставить в Стоимость»** — записывает итог в поле ввода
  «Стоимость». **Не сохраняет в БД** — менеджер проверяет цифру и жмёт
  существующую кнопку «Сохранить».
- Состояние полей — локальное (`useState`), нигде не сохраняется.

### Связь калькулятора с полем «Стоимость»

`OrderPriceInput` сейчас держит значение поля в собственном `useState`.
Чтобы калькулятор мог подставить туда число, состояние поднимается в
общий клиентский компонент-обёртку `components/admin/OrderPricing.tsx`,
который рендерит и `OrderPriceInput` (становится управляемым), и
`CostCalculator`. Кнопка «Подставить в Стоимость» вызывает сеттер обёртки.

### Клиентская часть

В `components/order/SummaryPanel.tsx` вызов `calculatePrice` заменяется на
`estimatePrice` из `lib/pricing.ts` — та же модель с дефолтными тарифами и
оценкой времени печати из веса. Покупатель видит **только итоговую цифру**,
без разбивки (как сейчас, блок «Ориентировочная стоимость»).

Старый `calculatePrice` удаляется из `lib/utils.ts`.

## Тестирование

Юнит-тесты на `lib/pricing.ts`:
- известные входы → известный итог (проверка всей цепочки формулы);
- граничные случаи: брак 0%, время 0, наценка 1.0, налог 0%;
- оценка веса из габаритов;
- оценка времени из веса.
